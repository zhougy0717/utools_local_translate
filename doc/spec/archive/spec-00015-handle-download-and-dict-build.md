在mode命令中，如果对应的资源目录没有词典时，则显示词典未下载，针对模型同理
如果在词典未下载的状态下，选择离线词典模式，则弹出词典下载方法的说明。
如果词典已下载未处理，则触发处理过程，将其转换为查词可用sqlite数据库，处理转换过程通过列表文字显示进度（当前仅考虑下载ecdict项目的ecdict-sqlite-28.zip，其转换处理主要是解压提取 ecdict.db 和删除原压缩包）。
如果词典已下载且已处理完成，则模式选择命令的下拉列表中显示词典已就绪

## 软件方案设计

### 1. 资源状态判定逻辑

在生成 `/mode` 命令列表前，需要对当前模型或词典目录的文件进行探测，划分不同的状态流：

*   **定义状态枚举**：
    *   `READY` (已就绪)
    *   `DOWNLOADED_UNPROCESSED` (已下载未处理)
    *   `UNAVAILABLE` (未下载)
*   **词典状态判定**：
    *   读取用户配置的 `dictRepoPath`（如果未配置则读取 `resources`）。
    *   **已就绪**：目录下存在 `ecdict.db`。
    *   **已下载未处理**：如果 `ecdict.db` 文件不存在，但目录下检测到了已下载的压缩包 `ecdict-sqlite-28.zip`。
    *   **未下载**：以上文件均不存在。
*   **模型状态判定**：
    *   读取模型路径配置，检查模型运行所需的二进制文件是否存在，存在则为 `READY`，否则为 `UNAVAILABLE`。

### 2. UI交互拓展 (`commands/mode.js`)

在用户输入 `/mode` 时，修改列表项的 `description` 以包含实时资源状态，示例：
*   离线词典模式 (已就绪)
*   离线词典模式 (已下载未处理)
*   离线词典模式 (未下载)

### 3. 选择逻辑的处理分发

当用户通过 `handleSelect` 点选了某个模式后，根据先前判定的状态进入不同业务流：

*   **若为 UNAVAILABLE (未下载)**：
    *   如果选择离线词典模式，则弹出词典下载方法的说明（通过渲染新的一组包含详细下载链接和操作步骤说明的静态列表，或者打开网页）。针对模型同理。
    *   不切换当前的运行策略，保持在此停靠。
*   **若为 DOWNLOADED_UNPROCESSED (已下载未处理)**：
    *   阻止直接模式切换。
    *   开始执行词典处理过程（解压 `ecdict-sqlite-28.zip` 并提取出 `ecdict.db`，最后删除压缩包）。
    *   **进度展示**：将处理过程的回调信息（例如：`正在解压压缩包...`, `已提取 ecdict.db...`, `清理完毕，处理完成！`）通过传递进来的 `callbackSetList` 函数呈现出来，让用户在 uTools 的列表文字中实时看到处理状态。
    *   **成功后处理**：处理完成后，将状态更新为“已就绪”。
*   **若为 READY (已就绪)**：
    *   正常执行原有的模式切换逻辑。

### 4. 数据处理模块 (`backends/dict/builder.js`)

*   **独立的Builder模块**：创建一个新的模块封装，专职负责对下载完毕的文件（当前仅针对 `ecdict-sqlite-28.zip`）进行后处理。
*   **解压文件**：采用 Node.js 环境兼容的解压逻辑（例如引入 `adm-zip` 或其它通用 zip 操作库），将 `ecdict-sqlite-28.zip` 解压出核心 SQLite 文件（如果是 `stardict.db` 则将其重命名为 `ecdict.db`），并放置至同级目录。
*   **清理现场**：成功解压且验证生成的 `.db` 文件无误后，通过 `fs.unlink` 删除原始的 `ecdict-sqlite-28.zip` 文件，释放用户本地磁盘空间。
*   **进度暴露**：提供 `build(sourcePath, destPath, onProgress)` 方法。在执行的关键节点（如开始读取 zip、解压中、文件提取完毕、旧压缩包清除完毕）向 `onProgress(message)` 回调发送指令，驱动 UI 层更新。

### 5. 开发计划

*   **第一步：增加资源探测与状态枚举定义**
    *   在加载 `/mode` 命令数据或相关生命周期初始化时，加入对词典和模型目录文件的存在性探测。
    *   梳理并返回 `READY`, `DOWNLOADED_UNPROCESSED`, `UNAVAILABLE` 的枚举状态。
*   **第二步：更新 UI 列表渲染逻辑**
    *   修改 `commands/mode.js`，将探测出的实时状态映射到命令项的 `description` 副标题中。
*   **第三步：实现数据压解与清理模块 (Builder)**
    *   新增 `backends/dict/builder.js`。
    *   编写利用如 `adm-zip` 解压 `ecdict-sqlite-28.zip` 的逻辑，并实现 `onProgress` 回调。
    *   编写并在解压成功后安全删除原始 zip 的收尾逻辑。
*   **第四步：重构模式切换的分发逻辑**
    *   修改 `commands/mode.js` 或对相应的 `handleSelect` 事件处理器，根据状态分发：
        *   `UNAVAILABLE` -> 阻断并显示下载获取说明。
        *   `DOWNLOADED_UNPROCESSED` -> 阻断，调用 Builder，通过 `callbackSetList` 实时刷新解压状态，完成后重置状态。
        *   `READY` -> 执行原有的模式切换及相关状态清理工作。
*   **第五步：测试与验证**
    *   模拟目录缺少文件的情况下，测试 UI 阻断和说明展现。
    *   放入伪造的或真实的 `ecdict-sqlite-28.zip`，拦截模式选择并验证转换进度的流式打印及最终完成的结果。
    *   验证解压产生的 SQLite 功能是否正常，验证压缩包是否被正常销毁。
