接口清理：统一 ListItem 契约

将业务逻辑与 UI 展示彻底剥离 (方案 A)

当前设计（数据臃肿）

Handler 返回值示例 (OfflineDict)
{
  title: "离线词典 (已激活 🌟)",
  description: "✅ 词库已就绪 — 使用 ecdict...",
  icon: "icons/dict.png",
  modeId: "offline_dict",
  currentStatus: "READY", // 业务字段
  extInfo: { ... },       // 业务字段
  isCommandContext: true,
  commandTrigger: "mode"
}

⚠️ 问题：这些字段在 handleSelect 中又被重算了一次，属于冗余数据。

理想设计（极致精简）

统一 ListItem 接口
{
  // 仅包含 UI 展示必需字段
  title: String,
  description: String,
  icon: String,

  // 仅包含路由与交互必需字段
  modeId: String,
  isCommandContext: true,
  commandTrigger: "mode"
}

✅ 优点：所有 Handler 返回一致，逻辑严谨，单一职责。

统一所有 getSearchItemData 的返回值为标准 ListItem
